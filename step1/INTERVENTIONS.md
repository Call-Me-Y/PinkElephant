# 失败历史的直接干预：48个失败点的实际生成评测

本轮从概率倾向进入实际动作测试。数据仍是pilot的24个任务、一次和两次失败共48个检查点。
每个方法都让模型自行生成并执行最多三步，每步最多96 tokens，greedy，最终由ToolShed目标判据决定成功。
测试参考动作只用于离线评测和独立训练数据的监督，不进入测试解码器或约束器。

主配置：`configs/interventions_v1.json`。完整批量runner在运行时记录batch=4、FP16主干/FP32分数、输出目录等解析后的配置到manifest。
独立训练世界seed=20261114，48个任务、96个失败点；评测世界seed=20261113，24个任务、48个失败点。
训练数据可由 `train_intervention_heads.py` 调用现有生成器重建。相同任务模板仍会重用，不是跨领域泛化。

| 条件 | 行为 |
|---|---|
| drop | 删除失败调用与观察，不提供任何新反馈 |
| verbatim | FTB原版失败调用和错误回显 |
| abstract | FTB原版抽象反馈 |
| positive_history | 前一轮的历史感知正向提示 |
| ftb_ban | 原始回显，按FTB规则屏蔽完整失败串的最后一个token |
| abstract_ban | 在抽象反馈上加相同字符串禁用，控制基础上下文 |
| local_constraints | 抽象反馈，加错误证据触发的局部生成约束 |
| contrast_025 / 05 / 1 | 抽象反馈分布，扣除回显增量，λ预先固定为0.25/0.5/1 |
| sft_head | 独立训练的低秩输出头，只使用正确动作监督 |
| ul_head | 相同训练，加上对失败调用首个分歧token的unlikelihood损失 |

局部约束只处理当前未解决窗口中已观测到的指定工具/错误族：必需字段、公开参数名和日期/时间/邮箱格式。
它不会从测试gold中获取字段值。成功工具调用后撤销本窗口规则。合法调用也可能偏离目标或提交空正文。

对比解码在每个生成位置计算三个上下文：FTB abstract、中性回显、删除失败历史。
生成分数为 log p_abstract − λ max(0, log p_neutral − log p_drop)，再将基础abstract分布中低于最大概率0.1倍的token排除。
这是一种待验证的操作性干预；增量可能包含合法共享信息，不代表已经识别了独立的复制神经机制。
同一生成token同步送入三个上下文的KV缓存。需要三分支计算，因此不是与普通解码等算力的比较。

训练使用rank=8、alpha=8的输出头适配器，四轮、学习率0.001、UL权重1，冻结完整主干。
SFT与SFT+UL初始参数、数据顺序、监督目标完全相同。UL只惩罚错误序列与正确序列首个分歧token，保留共享正确前缀。
这不是完整LoRA、全参数微调或UL原论文复现；作用范围仅限这个小型训练方案。

## 运行与恢复

初次训练入口（已有一致的训练文件会跳过）：

```powershell
Set-Location C:\Projects\AI\PE\step1
python scripts/run_interventions.py --train-only
```

训练文件已经保存在 `results/interventions-v1`。完整正式pilot从头用批量runner评测，复用该目录中训练完成的两个输出头：

```powershell
python scripts/run_interventions_batched.py
python scripts/summarize_interventions.py
```

结果目录为 `results/interventions-batched-fp16-v2`。断点按case_id和arm跳过已完成轨迹。
早期串行、BF16和FP32/TF32的数值或性能诊断分别保留，不混合分数。
最终FP16版本的九组上下文首token与八token缓存续写一致，下一token分布最大KL约0.000353，
最大logit绝对差约0.102。低精度批量计算存在舍入差异，这些检查不保证所有后续token逐位相同。
所有评测方法使用同一最终推理精度；训练适配器仍保留已完成的BF16冻结主干训练版本。

## 如何读结果

主指标是三步内环境任务成功率，辅以首步有效、原失败调用的规范化重复、同工具同错误类型再现、截断与计算量。
同工具同错误类型是粗粒度的同错代理，不覆盖全部语义策略。字符串禁用让逐字重复降低具有构造性，不能单独证明恢复。
不同历史深度是相关观测，按24个任务做聚类bootstrap，10,000次；子组与λ敏感性属探索，不选择最有利一组当独立确认。
UL必须与SFT-only比较；即便优于无训练基线，也不能将全部收益归因于排斥训练。

所有生成动作会被汇总脚本在环境中独立重放，核对保存的结果和成功指标。
费用统计不涉及API；tokens、分支数和GPU批量摊销时间见costs.csv，摊销时间不是单请求延迟。

这些失败由固定扰动人工注入，不保证是模型在干净上下文中自己会选择的动作。
因此drop重复率很低不能推出自然失败时删除反馈总是有效；正式研究还需对模型自产失败做同前缀分叉。
本轮可作为后续方案筛选，不能替代独立任务世界确认与更强模型实验。

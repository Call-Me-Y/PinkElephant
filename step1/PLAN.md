# 最小可行实验与 7–8 周工作计划

## 第一阶段只回答一个小问题

在同一个已发生失败的工具调用状态上，相比原始回显和 FTB 抽象反馈，基于历史计数的正向引导，
能否减少**随后实际执行的失败动作重复**，并保留三步内完成剩余任务的能力？

首个改动只增加一个规则：未解决窗口中同一个 `(tool, error_type)` 第二次出现时，
提示从直接补齐字段/格式加强为“先核对 schema，未知值先查询，再执行”。
内部保留失败动作帮助诊断，任务模型看到的卡片仅包含公共 schema 与修复要求。
没有训练、LLM 裁判、学习式检索、跨任务记忆或成功修复规则的自动写入。

这是对 FTB 环境的**行为实验扩展**，不是复现其 log-probability 分解，也不等于完成 Sentry 复现。
FTB 抽象反馈已经存在，首版的增量是历史感知引导及其隔离通道的受控验证；创新性需要后续证据支持。

## 最小实验如何做

1. 复用 FTB 的任务生成、工具 schema、错误扰动和环境成功判据；不改工具执行逻辑。
2. 首轮选三个可诊断错误族：缺少参数、参数名不匹配、格式错误，每类八个不同任务。
3. 用参考轨迹抵达一个可达失败点，注入经环境确认的错误动作一次或两次。
   验证失败不改变世界，且原参考后续仍可完成任务；每个独立任务只取一个失败点。
4. 从相同世界和成功前缀分别开始五种条件，模型自己生成最多三步动作；没有候选项或正确调用提示。
5. 每个失败点的条件顺序固定随机化。输入预算、动作预算、模型设置保持一致；反馈长度真实记录。
6. 保存完整轨迹，按独立任务聚类比较两种历史深度，避免把同一任务的多个副本当作独立样本。

三类错误是首版能力范围，不代表所有失败情况。格式错误包括日期、时间或邮箱等工具规范。
数据由规则选取，可能偏向 schema 可修复的任务；自由运行是检验这一局限所需的后续步骤。

## 五条件各自能说明什么

| 比较 | 可检验的问题 | 限制 |
|---|---|---|
| abstract vs verbatim | 在本模型上能否观察到 FTB 的最终动作趋势 | 输入信息和表达形式一起变化 |
| positive_current vs abstract | 当前错误的正向修复要求是否有效 | 包含更具体的 schema 线索，不单独证明正向措辞效应 |
| positive_history vs positive_current，history=2 | 历史计数触发的加强要求是否带来增益 | 计数与新增提示共同变化；无效时说明首版历史策略不够 |
| positive_history vs verbatim_positive | 相同正向卡片下移除失败动作与报错是否有收益 | 也改变上下文长度和原始诊断信息，不能完全归因为字符串启动效应 |
| history=1 时的两个正向条件 | 检查两条件输入确实相同 | 不增加独立样本量，API 的微小差异可能来自服务随机性 |

若数据支持再补等长度中性文本对照，单独消融“次数”与“加强提示”两个部分。
首轮五组已经能分清是否值得继续，不应先堆叠更大的方法系统。

## 指标与预定解释

主指标：**下一步等价重复率**。对模型生成的首个动作做 FTB 同款规范化，判断是否等于已注入的失败调用。
规范化覆盖引号、空白、关键字参数顺序，不能覆盖所有语义相同的失败策略。

同时报告：下一步精确重复率、三步内再次执行该失败调用的比例、首步有效率、三步内环境任务成功率、
生成失败数、输入输出 tokens 与耗时。有效调用可能与目标无关，所以首步有效率不能替代恢复或任务成功。
三步内任务成功是严格恢复指标，会遗漏“有实质进展但未完成”的样本；对这些样本人工审查。

历史策略的预定主比较是 `positive_history - positive_current`，限定 history=2。
隔离通道比较为 `positive_history - verbatim_positive`；与 abstract 的比较用于判断是否保留效用。
下一步重复率差值越小越好，任务成功率差值越大越好。其他指标与分组先作探索性报告。

主分析：对齐 checkpoint 与 sample，先对任务内的重复观测平均，再对独立任务做 cluster bootstrap。
小样本的区间可能很宽，也可能在全零时退化；零重复和包含 0 的差值区间都不支持强因果或普遍结论。
首版普通 bootstrap 区间不作多重比较校正；确认报告预先指定一个主比较，其余标为探索性。

Pilot 的决策阈值是人为设定的工程门槛：重复率下降约 10 个百分点且任务成功率没有明显下降，
值得扩样；该阈值不等于显著性标准。先观察配对差值分布，再决定正式确认所需任务数。
可把“成功率下降不超过 5 个百分点”作为后续非劣目标；只有差值区间支持时才能声称非劣，
60 个任务不保证有足够把握证明这一点。

若原始模型重复率已低于约 5%，优先报告该任务分布上的低发生率，转查自然失败和更复杂错误。
不要在看完确认结果后反复换失败点来获得正结果。确认集开跑前固定扩样规则和最终判据。

## 模型、硬件和预算

| 角色 | 已有资源 | 用途 |
|---|---|---|
| 流程检查 | 无模型的 reference test double | 验证数据、计数、报告；无研究效力 |
| 真实模型连通检查 | 本地 Qwen2.5-0.5B-Instruct，CPU 或现有环境 | 检查动作提取、执行、保存；能力弱，不作为强模型结论 |
| 首轮主模型 | 已下载的 Qwen3.5-9B GGUF Q4_K_M + 现有 llama.cpp 服务 | 沿用已有 8G 显存部署，不重复加载权重 |
| 可选第二模型 | 已开通 API 中的一个固定指令模型版本 | 检验模型差异；先做两条检查，不依赖 log-probs |

Pilot：24 个任务 × 两种历史 × 五条件 × 至多三步，最多 720 次调用/模型。
若平均输入 T_in、输出 T_out tokens，则 token 上界估计为 720×T_in 与 720×T_out；
先用两个失败点量出实际均值，再按服务商的对应模型价格估费。首版不预填价格或付款方式。

确认：不同世界 seed，60 个任务 × 两历史 × 五条件 × 三次采样 × 至多三步，最多 5,400 次调用。
自然运行 pilot：同一批24任务 × 五条件 × 至多八步，最多 960 次调用。
不必首轮就跑两模型全部组合；先在一个模型上检查是否有信号，再投入第二模型。

## 第一个 7–10 天可交付成果

| 时间 | 具体工作 | 可交付物 / 验收 |
|---|---|---|
| 第1–2天 | 固定代码、生成24任务48失败点、核对来源与无副作用 | 数据 manifest；五条件输入例子；运行流程检查通过 |
| 第3天 | 接通本地模型，先跑两个失败点 | 真实模型逐步轨迹；动作解析率；单任务用时与token估计 |
| 第4–5天 | 主模型跑完整 pilot，人工看各类至少2条 | 五条件结果表、配对差值与区间、改善/退化样例 |
| 第6–7天 | 根据预定规则判断扩样或修改；检查失败动作通道 | 实验小结；卡片重合审计；修改记录；下一版冻结配置 |
| 第8–10天 | 开始冻结确认集或自由运行，对照单次注入的局限 | 第一版可汇报文档，明确哪些是证据、哪些仍是假设 |

允许初步结果为“低发生率”“没有收益”或“重复少但成功率下降”。这些都比预设改进有效更能指导后续工作。

## 7–8 周推进

| 周 | 主线 | 完成判据 |
|---|---|---|
| 第1周 | 数据、规则监控器、配对runner、主模型pilot | 第一张真实模型表与逐步样例；完成实验登记 |
| 第2周 | 检查解析/截断/信息丢失；冻结模板与确认方案 | 单一预定主比较；分离pilot与确认世界；明确扩样规则 |
| 第3周 | 独立世界确认；可行时加第二模型 | 任务聚类区间；模型间一致性或差异；保留负结果 |
| 第4周 | 自由运行，不注入错误；审查相关推进与同错策略 | 报告自然错误发生率、最终成功率、重复率与误引导 |
| 第5周 | 在现有 Sentry/AppWorld 入口选固定10–20个开发任务集成 | 复用模型服务、任务ID与预算；先确认完整失败信息是否真被移出actor输入 |
| 第6周 | 与 base、FTB式抽象、Sentry原版做小规模比较 | 不把本监控器命名为Sentry；独立记录两套方法开销和任务成功 |
| 第7周 | 最关键消融、泄漏审计、失败类型分析与写作 | 只补影响主张的证据；整理可复现命令和报告 |
| 第8周（机动） | 增加确认样本或修复集成问题 | 固定版本、完整结果表、开题汇报和后续研究清单 |

第5–6周集成取决于ToolShed是否出现可重复的行为收益；无收益时转做受控消融和信息保留研究。
后续跨任务记忆需增加“只写入环境验证过的修复原则”和独立训练/评测任务划分，首轮不预先宣称实现。

## 审计与边界

自动审计覆盖注入卡片是否包含完整失败调用、长度至少4的失败字符串参数是否重合；工具名与字段名允许。
当前是保守的字面检查，不验证语义可还原性；数值重合不作为自动泄漏判据，避免常见数字误报，需人工审查。
对每类至少两个样本，人工核对提示有无透露隐藏答案、是否可重建错误参数、正确动作是否被误引导排除。
同一原始值也可能来自用户目标或成功观察，要区分合法证据来源与新增反馈泄漏。

本实验提供的是方法可行性与行为信号；最终成功率提高、普遍抑制错误、可迁移记忆和完整机制解释都需要额外实验。
